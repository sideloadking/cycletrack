## Design Specificity Verdict

**PASS.** The Route Atlas world — daylight surfaces, mono tabular data numerals, confidence pills, hatched uncertainty bands, the route ribbon — is a direct visual translation of the product's honesty promise. A competitor could not lift this look without also stealing the product stance. This is authored, not assembled.

## Cognitive Load

- Decision points with >4 visible options: the dashboard HR picker (4 options) and power picker (4) sit at the limit; the ride table has 8 columns.
- Checklist failures: page-head stacks three header layers (breadcrumb → eyebrow → h1 → paragraph); records page duplicates every fact twice; route detail with n=1 renders a 9-column table and a single-point chart.
- Wins: one task per page, consistent vocabulary, empty states that teach.

## Emotional Journey

- Onboarding: honest and reassuring ("Local by design", "physics gives a power band, not a fake precise number"). Strong.
- Peak: the ride replay — the linked cursors are a genuine "moment".
- Valleys: the singleton route detail (chart with one dot reads as broken), the map-badge/zoom collision, error copy that says "not found" twice.

## Priority Issues

- **[P1] Map badge collides with the Leaflet zoom control** — badge (x340–491) overlaps zoom (x336–368, y744–806) on every ride detail; the zoom-in button is partially occluded. Detector-verified.
- **[P1] Records page duplicates every fact** — the same six records render as cards AND a ledger table; 12 copies of 5 facts with one ride in the library. Pick one representation or make the ledger the interactive detail.
- **[P2] Sparse-data pages are overbuilt** — route detail with one ride shows a 9-column comparison table + a single-point progress chart; the singleton chart looks broken.
- **[P2] Two primary Import actions per view** — the topbar "+ Import ride" appears on every page including the profile form, alongside page-level Import primaries on dashboard/rides/routes.
- **[P2] Eyebrow/kicker stack above every heading** — eyebrow + h1 + paragraph after a breadcrumb = three stacked header layers; detector flags kicker-above-heading and hero-eyebrow-chip on every page.
- **[P2] Display tracking below the floor** — h1 −0.055em, hero h2 −0.065em (craft-floor: −0.04em max); detected as extreme-negative-tracking.
- **[P2] Page-head paragraph measure 87ch** (target ≤75ch); detected line-length.
- **[P3] HR zone boundaries entered twice** (Z1 hi == Z2 lo) — user can create discontinuous zones; validation only checks lo < hi per zone.
- **[P3] Jargon** — "W @ 140", "TRIMP", "CTL/ATL/TSB", "CdA/Crr", "NP" unglossed; "Tap a row" on a desktop app.
- **[P3] Dropzone double-frames** — outer card, dashed box, and an inset dashed ::before = three nested frames.
- **[P3] Sidebar foot at 10px** — flagged below the 11px floor; brand marking exemption is debatable.
- **[P3] Error copy** — "Route not found / not found" duplicates the server message.

## Minor Observations

- Decorative ::after circle motif repeats on record cards, route cards, and the hero (template tell).
- Monotonous spacing — 4px-derived gaps used 92% of the time; the 4px unit is a system but the rhythm is mechanical.
- Graph legend "text-occlusion" detector hits are false positives (measured rects show no overlap; legend is z-indexed above the SVG).
- `.uncertainty__track` clips its marker overhang — intentional but flagged.
- Leaflet attribution enlarged to 11px could use 2–3px more padding.

## Persona Red Flags

- Single owner, rides after the fact on a Windows machine: no persistence of selected HR/power duration across visits (re-visit resets to 140/5min); the dashboard is built for "many rides" but the owner has one ride today — the sparse-state design matters more than the dense-state design.
- The owner's two questions ("Am I fitter?", "Am I faster on this loop?") are answered on the dashboard and route detail — both currently show "not enough data" states, so the empty/singleton states ARE the product today.

## Provocative Questions

1. If the owner has one ride, why does the dashboard show four charts and the records page twelve copies of the same five facts?
2. Is the eyebrow earning its layer, or is it decoration the heading does not need?
3. What would this app look like if the topbar CTA were context-aware instead of omnipresent?
4. Does the route detail page need a comparison table and chart at n=1, or should it say "ride it again"?
