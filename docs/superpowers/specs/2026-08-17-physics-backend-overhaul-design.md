# Physics Backend Overhaul — Design Spec

Date: 2026-08-17. Status: approved (approach A). Goal: make power
estimates as accurate as physics allows, then tighten the uncertainty
bands *honestly*, gating every change on a synthetic eval harness. The
honesty contract stands: no power meter means some uncertainty is
irreducible, and we never pretend otherwise.

## 1. Objectives

1. Remove systematic bias from the point estimate:
   - crosswind-aware aero drag (drag scales with `|v_air|`, not the
     headwind component),
   - elevation-aware air density (barometric pressure + temp lapse per
     point instead of one constant for the ride),
   - wind-recovering calibration (jointly fit crr, CdA, wind speed,
     wind direction on loops/out-and-backs).
2. Reduce noise without bias: zero-phase speed smoothing before
   differentiating (Savitzky–Golay), time-windowed metric integrals,
   robust regression.
3. Make the bands honest after the bias is gone: per-ride wind variance
   from weather, calibration covariance for crr/CdA, and a coverage
   test that proves the 2-sigma band contains the true power at the
   claimed rate.
4. Keep every existing behaviour/API stable (storage schema, server
   endpoints, test suite) unless a change is deliberate.

## 2. Eval harness (the quality gate)

`tests/physics_eval.py` — synthetic rides generated by forward
integration of the real dynamics with **known** (crr, CdA, wind speed,
wind direction, mass, rho). Checks:

- **E1 recovery:** `calibrate_loop` / `calibrate_loop_wind` recover the
  injected crr and CdA within tolerance on a loop ridden in crosswind
  (today this is biased — that is the bug we fix first).
- **E2 point accuracy:** on a synthetic climb with known physics,
  `compute_power` matches the true power within a tight tolerance on
  gravity-dominated segments.
- **E3 band coverage:** over N simulated rides with random wind/grade
  errors, the true power lies inside `[watts_lo, watts_hi]` at ~95%
  (2-sigma) for the aggregate, and never below ~90%.
- **E4 coasting:** synthetic coasting descents are flagged `coast`;
  light pedalling with elevated HR is not.
- **E5 real ride:** the repo's `.fit` file parses and `compute_power`
  yields plausible ranges (no NaNs, median watts in 60–400 W window on
  pedalling points).

Gate rule: every iteration must keep all of E1–E5 passing. An iteration
that fails reverts.

## 3. Iteration plan (dependency-ordered)

1. **Harness** — build `tests/physics_eval.py`, wire a scoreboard
   (`docs/superpowers/specs/physics-eval-results.md`) recording each
   eval metric per iteration so progress and the plateau are visible.
2. **Crosswind drag** — `v_air = sqrt((v + hw)^2 + cw^2)`,
   `F_aero = 0.5 rho CdA |v_air| (v + hw)`; propagate through
   uncertainty derivatives.
3. **Elevation-aware rho** — barometric formula
   `P(z) = P0 (1 - Lz/T0)^(gM/RL)` and temp lapse per point using each
   point's elevation; surface values from weather.
4. **Wind-recovering calibration** — grid over (wind speed, direction)
   × linear least squares for (crr, CdA) on coasting segments, pick the
   best residual; fall back to the wind-free fit when it does not
   converge or the wind estimate is not identifiable.
5. **Zero-phase speed smoothing** — Savitzky–Golay on speed before the
   acceleration difference; keep the 5-point fallback for short rides.
6. **Coasting refinement** — require no recent acceleration surge; use
   HR evidence (HR below ~0.78·max) when HR exists.
7. **Robust calibration** — Huber loss / segment-length weights;
   report parameter covariance; per-calibration sigma for the bands.
8. **Honest bands** — per-ride wind sigma from weather (gust/var),
   calibration covariance, and E3 coverage as the acceptance test.
9. **Metric fixes** — time-windowed best-power integrals, robust
   watts@HR, normalised power excluding coasting.
10. **Diminishing-returns sweep** — try yaw-dependent CdA, wheel
    rotational inertia, temperature-dependent Crr; keep only what
    moves E1–E5 beyond the noise floor.

## 4. Stopping rule ("impossible to improve")

The loop stops when a candidate iteration fails the gate or moves the
eval metrics less than the run-to-run noise floor (measured by
re-running the harness with different seeds). The final report states
the remaining ceiling explicitly: **wind is not fully separable from
CdA on single-direction rides without a power meter — that is an
information limit, not an implementation gap.**

## 5. Risks / mitigations

- **Overfitting the harness:** the synthetic generator must use the
  same dynamics the model assumes; recovery tests use *different* noise
  seeds and the real `.fit` file as an out-of-sample check.
- **Worse bands from tighter estimates:** E3 coverage is the guard —
  bands shrink only while coverage holds.
- **Regression risk:** the existing `tests/verify_backend.py` runs in
  the gate every iteration.
